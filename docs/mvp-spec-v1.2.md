## 1. 定位

**台股短線趨勢轉弱偵測與持股風險管理工具。** 不是買賣訊號產生器，也不預測漲跌幅。

成功標準：長期而言，依警報減碼所避開的損失，大於錯誤警報造成的少賺與交易成本；
而且這個效果**必須優於條件相同的隨機警報**（§6.4），證明不是單純因為平均持股較低。

第一版以**大盤**風險為主；資料表與程式結構保留擴充到產業、個股風險分數的空間（§8），
因為使用者實際操作以個股為主。

## 2. 開發順序與驗收標準

採「A 訊號研究 → B 風險分數與減碼回測」。

| Phase | 內容 | 驗收標準 |
|---|---|---|
| **1 價格資料** | 加權、櫃買、台積電日 K（2005 起）、台積電除權息、費半與 Nasdaq 日 K（國際同步條件用） | 全期間每個交易日都有 OHLC；與官方數值抽查一致；可中斷續跑；每日更新可在 Windows 執行 |
| **2 訊號研究（A）** | 第一批：高檔跳空向下系列（§4）。訊號後 1／3／5／10／20 日表現，與無條件基準比較 | 產出研究報告：每個訊號變體的次數、後續報酬分布、與基準差異、探索期與驗證期是否一致 |
| **3 市場廣度** | 上市櫃漲跌家數、漲跌停（官方）；個股均線分布與新高新低（需全市場個股，評估後再做） | 2012 起每日完整，缺漏日明確標示 |
| **4 籌碼整合** | 既有期貨模組、上市櫃三大法人現貨、融資餘額 | 期貨模組不改寫，只新增讀取 |
| **5 風險分數與減碼回測（B）** | 通過研究的訊號進入分類別分數；減碼參數網格回測；隨機警報比較 | 回測報告：各參數組合的報酬、回撤、少賺、避損，以及相對隨機警報的百分位 |
| **6 每日流程與網站** | Windows 排程；產生 JSON；部署 Cloudflare Pages＋Access | 家中電腦關機時網站仍顯示最後一次成功發布的資料 |

網站骨架可以提早建立，但不得拖慢 Phase 1～5。

## 4. 第一批訊號：高檔跳空向下

### 4.1 共用定義

所有幅度以 ATR(20) 標準化，同時保留百分比數值供比較。只用 t 日收盤以前的資料。

| 名稱 | 定義 | 參數（預設） |
|---|---|---|
| ATR(n) | 真實波動 TR = max(H−L, \|H−C₋₁\|, \|L−C₋₁\|) 的 n 日簡單平均，取到 t−1 | n=20 |
| 高檔 `high_zone` | t−1 日收盤位於近 N 日（至 t−1）高低區間的上方 q，**或**距 N 日最高價 d 以內 | N=60, q=0.8, d=5% |
| 嚴格跳空 `gap_strict` | H_t < L_{t−1} | |
| 開盤跳空 `gap_open` | O_t < L_{t−1} | |
| 跳空幅度 | (L_{t−1} − O_t) / ATR，以及 (L_{t−1} − O_t) / C_{t−1} | |
| 收盤跌破前日低點 | C_t < L_{t−1} | |
| 缺口未回補 k 日 | 跳空當日（第 0 日）到第 k 個交易日的最高價都 < L_{t−1}（缺口上緣）。開盤跳空但當日盤中已回補者不算 | k=3, 5 |
| 量能放大 | 成交金額 / 20 日均成交金額（至 t−1） | 門檻 1.5 |
| 櫃買同步 | 同日櫃買也開盤跳空，或櫃買收盤跌破前日低點 | |
| 國際同步 | 對齊的前一美股交易日，費半日報酬 ≤ −1.5 倍自身 ATR%，或收盤 < 20 日均線 | |

「缺口未回補 k 日」要到 t+k 日才知道。研究時以 **t+k 日**作為訊號日，不能回填到 t 日。

### 4.2 研究變體

基礎事件：`high_zone ∧ gap_open`。在此之上比較：

1. 嚴格跳空 vs 開盤跳空
2. 跳空幅度分組：< 0.5、0.5–1、≥ 1 ATR
3. 收盤是否跌破前日低點
4. 缺口未回補 3 日／5 日（訊號日為 t+3／t+5）
5. 量能放大與否
6. 櫃買同步與否
7. 國際同步與否
8. 對照組：非高檔的跳空向下（檢驗「高檔」本身是否有意義）

變體清單在看到結果前固定，報告列出**全部**結果，不只列最好的。

### 4.3 研究方法

- 標的：加權指數為主，櫃買為輔。
- 結果指標：訊號日收盤後的 1／3／5／10／20 日報酬，以及期間內最大不利跌幅（以 ATR 與 % 表示）。
- 基準：同期間所有交易日的同一指標分布；以及「高檔但未跳空」的交易日。
- 期間切分：**探索期 2005–2018、驗證期 2019–今**。只有兩期方向一致的變體才進入 Phase 5。
- 重疊樣本：相鄰訊號的後續期間重疊會誇大樣本數。報告同時列出「去除後續 20 日內重複訊號」後的結果。
- 次數太少（< 15 次）的變體只列出、不下結論。

### 4.4 gap-v2（2026-11-12）

- 量能放大改為「量比在過去 750 日中的百分位 ≥ 80%」。原本的「量比 ≥ 1.5」對指數幾乎不會發生（約 2% 的交易日）。
- 其餘定義不變。gap-v1 設定凍結於 `src/twtm/signals/gap-v1.toml`，報告保留在 `reports/gap-v1/`。

### 4.5 研究方法 research-v2：以「大回檔機率」判定

訊號的意義是**警訊**，不是預測下跌。主要判定改為：

- **回檔機率**：訊號日收盤後 20 個交易日內，最低價 ≤ 訊號日收盤 − 4 ATR（ATR 含訊號日）。
  基準約 26%（加權）、30%（櫃買）。另列「回檔 ≥ 5%」作為輔助。
- 判定：兩期回檔機率都高於所有交易日 → 「兩期回檔機率皆較高」；兩期自助抽樣 p 都 < 0.10 → 加註顯著。
- 平均報酬仍然列出，作為參考。
- 自助抽樣的亂數由（變體、期間、指標）決定，新增指標或變體不影響既有結果。

## 4A. 跌破均線系列（ma-v1）

均線含 t 日。只在條件「由不成立轉為成立」的那天產生訊號。

| 變體 | 定義 |
|---|---|
| M1–M3 | 收盤由上往下跌破 5／10／20 日線 |
| M4 | 跌破 20 日線後連續 3 日收盤都在 20 日線之下（訊號日為第 3 天） |
| M5 | 5 日線由上往下穿過 20 日線 |
| M6 | 20 日線開始下彎：今天 < 3 日前，且前一天還不是下彎 |
| M7 | 連續 3 日收低（第 3 天，不含更長連跌的延續） |
| M3u／M4u／M5u | M3／M4／M5 且「多頭中」：t−1 的 20 日線 > 60 日線 |

對照基準：多頭中的所有交易日。

## 4B. 假突破系列（fb-v1）

「創高」＝突破前 60 日（長期版 250 日）最高價。

| 變體 | 定義 |
|---|---|
| B1 | 盤中最高 > 前 60 日最高，收盤 < 前 60 日最高 |
| B2 | 收盤突破前 60 日最高（突破位 L），之後 3 日內收盤 < L；訊號日為收回那天 |
| B3 | B1 或 B2，且被突破的高點形成於 ≥ 10 日前，其間最低價曾比該高點低 ≥ 2 ATR（創高、拉回、再創高、又失敗） |
| B4 | B1 或 B2 之後 10 日內出現開盤跳空向下（訊號日為跳空日） |
| B1L／B2L | 同 B1／B2，改用前 250 日最高 |

對照基準：高檔的所有交易日。

## 5. 風險分數（Phase 5，此處先定架構）

- 四類別：價格趨勢、市場廣度、籌碼、國際市場；各 0～1，加權合成 0～100。
- 只有通過 Phase 2 研究的訊號可以進入分數。權重先用簡單規則（類別內等權），避免調參過度擬合。
- 等級（初版，需回測校準）：

| 分數 | 狀態 |
|---|---|
| 0–29 | 正常 |
| 30–49 | 留意 |
| 50–69 | 警戒 |
| 70–100 | 高風險 |

- 重要類別資料缺漏時，分數標記為不完整，不得顯示為正常。

## 6. 減碼回測（Phase 5）

### 6.1 參數化（不寫死）

| 參數 | 測試值 |
|---|---|
| 警戒時持股比例 | 80%、70%、60% |
| 高風險時持股比例 | 60%、40%、20% |
| 恢復條件 | 分數連續 k 日低於「留意」門檻，k = 1、3、5；或收盤站回 20 日均線 |
| 執行時點 | t 日收盤產生訊號 → t+1 日開盤執行（主要）；t+1 日收盤執行（敏感度） |
| 交易成本 | 每次調整部位：調整比例 × 單邊成本；預設 0.3%（含稅費），另測 0.1%、0.5% |

警戒持股比例必須 ≥ 高風險持股比例；不合理組合自動略過。

### 6.2 標的

第一版用加權指數報酬代表大盤曝險。使用者實際持有個股，所以報告要註明：大盤回測只證明
「大盤風險訊號」的價值，不等於個股組合的實際效果。個股與產業回測在擴充階段處理（§8）。

### 6.3 指標

- 整體：年化報酬、最大回撤、報酬／回撤比、平均持股比例、每年切換次數、總交易成本。
- 每次警報：持續天數、期間大盤報酬；少賺 = 減碼比例 × max(0, 期間報酬)；避損 = 減碼比例 × max(0, −期間報酬)。
- 彙總：總避損 − 總少賺 − 交易成本。
- 比較對象：一直滿倉、跌破 60 日線減碼（同一組減碼參數）、隨機警報（§6.4）。

### 6.4 隨機警報（公平比較）

每次模擬保持以下條件與系統**相同**：

| 控制項 | 做法 |
|---|---|
| 警報次數 | 相同 |
| 每次警報持續天數 | 直接沿用系統的持續天數序列（打亂順序） |
| 減碼幅度 | 每段沿用系統該段的持股比例 |
| 平均持股比例 | 由上兩項自動相同 |
| 切換次數與交易成本 | 由上兩項自動相同 |

只隨機化警報**起始日**，且各段不得重疊。模擬 1,000 次，報告系統結果在隨機分布中的百分位。

兩種隨機版本都要做：
1. **無條件**：起始日可以是任何交易日。
2. **條件相同**：起始日只從「高檔」交易日抽樣。這是較嚴格的檢驗，可以看出訊號是否比「單純在高檔減碼」更有價值。

### 6.5 避免過度擬合

- 參數網格結果全部列出，不只報告最佳組合。
- 探索期選參數、驗證期評估；之後改為 walk-forward（每年滾動）。
- 訊號與分數規則有版本號，每次回測記錄規則版本、資料截止日、程式版本。

### 6.6 第一版實作（pw-v1、bt-v1，2026-11-13）

**價格趨勢轉弱程度 pw-v1**：由 M4、M5、M6 改成每日狀態，三者高度相關，合成一個程度而不各自加分。

| 程度 | 條件 | 減碼層級 |
|---|---|---|
| 0 正常 | A、B、C 都不成立 | 滿倉 |
| 1 初步轉弱 | 成立 1 項 | 初步 |
| 2 明顯轉弱 | 成立 2 項以上 | 明顯 |
| 3 趨勢惡化 | A、B、C 同時成立連續 5 日 | 明顯（介面另外標示） |

A：收盤連續 3 日在 20 日線之下；B：5 日線 < 20 日線；C：20 日線 < 3 日前。

**回測 bt-v1**：
- 參數網格：初步 80／70／60%、明顯 60／40／20%（初步 ≥ 明顯）、恢復條件 3 種（轉弱程度連續 3 日低於目前層級；站回 20 日線；站回 20 日線且 5 日線上揚），共 27 組。
- 比較：全程 100%、全程固定 70%、全程固定「＝策略平均持股」、跌破 60 日線減碼、隨機警報。
- 隨機警報的第二個版本改為「**起始日限下跌日**」，取代 §6.4 的「高檔日」：價格訊號的減碼一定發生在下跌之後，
  這個版本檢驗訊號是否比「下跌後隨便減碼」更有價值，比高檔日更貼近這個策略。
- **選參規則**：只用 2005–2018 年，選「年化報酬 / 最大回撤」最高的組合；2019 年至今只用來檢驗。
- **保留驗證集**：M4、M5、M6 是看過全部歷史資料才選出的，所以歷史資料中沒有對「訊號選擇」完全乾淨的部分。
  真正未使用的驗證資料是 2026-11-12 以後的資料，之後每天累積，作為紙上模擬交易。
- 另外分析三個訊號的重疊程度，並把間隔 ≤ 10 個交易日的訊號合併成獨立風險事件後再統計。

### 6.7 bt-v2 事先登記（2026-11-13，執行前提交）

依 bt-v1 的發現（只出現單一訊號的風險事件之後很少出現大回檔），**訊號定義 pw-v1 完全不變**，只改使用方式：

| 項目 | bt-v1 | bt-v2 |
|---|---|---|
| 初步轉弱 | 持股 80／70／60% | **維持滿倉** |
| 明顯轉弱（含趨勢惡化） | 持股 60／40／20% | **80／70／60%** |
| 恢復條件 | 3 種 | 同左 |
| 成本情境 | 0.3% | **0.3%（賣股票）與 0.05%（期貨避險，只改成本，未模擬正逆價差與轉倉）** |
| 選參規則 | 2005–2018 年報酬/回撤最高 | 同左，各成本情境分別選 |
| 隨機警報 | 1,000 次，兩種起始日 | 同左 |

**成功標準（事先固定）**：各成本情境下選出的組合，在**檢驗期（2019 至今）**同時符合：
1. 報酬/回撤 高於「全程固定持有同樣平均持股」；
2. 報酬/回撤 優於 ≥ 90% 的隨機警報（起始日不限）。

**決策規則**：
- 股票情境通過 → 可以考慮當作機械式減碼規則。
- 只有期貨情境通過 → 另外做期貨避險的完整回測（計入正逆價差與轉倉）。
- 都不通過 → 轉弱程度只作為警示燈，不作為自動減碼規則。

加權與櫃買都跑；以加權為主要判斷依據。bt-v2 只執行一次，結果不論好壞都保留。

## 7. 資料表設計

### 7.1 Phase 1 新增

```sql
-- 標的主檔：指數、個股、ETF、海外指數；未來的產業籃子也放這裡
CREATE TABLE instrument (

-- 除權息與其他公司行動
CREATE TABLE corporate_action (
    symbol      TEXT NOT NULL,
    ex_date     TEXT NOT NULL,
    action      TEXT NOT NULL,     -- dividend | rights | both
    prev_close  REAL,              -- 除權息前收盤價
    ref_price   REAL,              -- 除權息參考價
    value       REAL,              -- 權值＋息值
    source      TEXT NOT NULL,
    fetched_at  TEXT NOT NULL,
    PRIMARY KEY (symbol, ex_date, action)
);
```

還原價不存表，由 `corporate_action` 即時計算（調整因子 = ref_price / prev_close），
規則改了不必重抓資料。

### 7.2 Phase 2 新增

## 8. 擴充到產業與個股

第一版只做大盤，但以下設計先到位：

- `instrument` 涵蓋任何標的；`price_daily` 以 `symbol` 為鍵，加個股不需改表。
- 訊號計算函式只吃一條 OHLCV 序列，不寫死加權指數，個股可以直接套用。
- `signal_event`、`risk_score` 都有 `scope`，可以是 `market`、`symbol:2330` 或 `sector:PCB`。
- 產業籃子（未來）：`basket_member(basket, symbol, weight, valid_from, valid_to)`，
  保留成分變更紀錄，避免存活者偏差。
- 個股必須使用除權息調整，因此 `corporate_action` 從第一版就建立。
