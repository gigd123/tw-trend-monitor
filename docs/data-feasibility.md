# 資料來源可行性評估

- 評估日期：2026-11-12（參考交易日 2026-11-11）
- 方法：每個來源實際打 API，確認回應格式、最新日期、最早可取得日期。
- 執行環境：雲端容器（資料中心 IP）。**國發會、BLS 在此環境被擋**，需在實際排程環境再驗證（見第 5 節）。
- 重跑方式：`python feasibility/probe.py`

---

## 1. 結論摘要

1. **Phase 1 需要的資料，絕大多數都能免費、合法取得**，而且多數來自官方（證交所、櫃買中心、期交所、FRED）。
2. 最大的限制不是取得不到，而是**歷史深度不一致**：
   - 期交所「三大法人期貨部位」官方下載只保留約 **3 年**（2023/11 可取得，2021 已取不到）。更早的資料要靠 FinMind（約 2020 年起可取得，更早未確認）。
   - 證交所「漲跌家數」約 **2012 年**起才有結構化資料（2009、2011 年的回應沒有這張表）。
   - 因此**回測期間的共同起點受限於籌碼資料**。價格類（加權、櫃買、費半、Nasdaq）可以回測 2000 年以後，籌碼類只能回測近幾年。
3. **需要自行計算**：散戶多空比、跳空缺口、均線、創新高新低家數、正逆價差。全部有原始資料可算。
4. **建議暫緩**：大盤融資維持率、Nasdaq 100 市場廣度、CPI／非農的市場預期值、FedWatch 機率。
5. 證交所有 **WAF**：短時間連續請求會回 307 導向「安全性考量」頁面，連線也偶爾被重置。回補歷史必須限速（建議每次請求間隔 ≥ 5 秒）並加上重試。
6. **各來源對 User-Agent 的要求互相衝突**：FRED 遇到自訂或偽裝成瀏覽器的 UA 會卡到逾時，只接受 requests／curl 的預設 UA；Yahoo 則會對 requests 預設 UA 回 429。adapter 必須各自設定 headers。

`probe.py` 最終結果：**36 項中 34 項通過**。失敗的 2 項是國發會（Cloudflare）和 BLS（Akamai），都是擋資料中心 IP。

## 3. 歷史深度與回測起點

| 資料群 | 可回補到 | 限制來源 |
|---|---|---|
| 價格（加權、櫃買、台積電、費半、Nasdaq） | 2000 | Yahoo 日線從 2000 起 |
| 美債、VIX | 1990 | — |
| USD/TWD（當日更新） | 2010 | TAIFEX |
| 上市三大法人、融資 | 2005 | — |
| 漲跌家數 | 約 2012 | TWSE 表格 |
| P/C Ratio | 2008 | — |
| **外資期貨部位、散戶多空比** | **約 2020（FinMind）／3 年（官方）** | 最短的一塊 |

建議回測分兩層：
1. **長期回測（2005～今）**：只用價格、美債、VIX、匯率、法人現貨、融資。可以涵蓋 2008、2011、2015、2018、2020、2022 等多次修正，樣本數足夠。
2. **短期回測（2020～今）**：加入期貨籌碼。只當輔助參考，樣本太少，不能拿來決定權重。

**期貨籌碼要從系統上線那天開始每天保存**，官方只保留 3 年，錯過就要靠第三方。

## 4. 需要寫死的計算口徑

### 散戶多空比（小台為例，微台同理）

> 2026-11-12 起，介面與後續文件統一改稱「非法人多空比（估算）」，計算方式不變。

```
全市場未平倉 OI  = Σ 小型臺指期貨各月份 OpenInterest（一般時段）
法人多單        = 自營商 + 投信 + 外資 的 OpenInterest(Long)
法人空單        = 自營商 + 投信 + 外資 的 OpenInterest(Short)
散戶多單        = OI − 法人多單
散戶空單        = OI − 法人空單
散戶多空比      = (散戶多單 − 散戶空單) / OI × 100%
               = (法人空單 − 法人多單) / OI × 100%
```
正值＝散戶偏多。

2026-11-11 實算（OpenAPI 資料）：

| 商品 | 全市場 OI | 法人多單 | 法人空單 | 散戶多空比 |
|---|---|---|---|---|
| 小台 MTX | 37,412 | 8,158 | 11,544 | **+9.05%** |
| 微台 TMF | 98,136 | 30,617 | 23,748 | **−7.00%** |

同一天兩個商品方向相反，這正是規格說的「不能將不同商品直接比較」。

口徑細節：
- 小台有**週到期契約**（如 `202611W2`），全市場 OI 要包含週契約，因為法人未平倉也包含所有到期月份。
- 排除價差組合列（月份欄含 `/`）與盤後時段列。

注意：「散戶」其實是「非三大法人」，包含大額自然人與非法人機構。UI 應標示為「非法人」或註明口徑。

### 跳空缺口
- 向上缺口：`low[t] > high[t-1]`，缺口區間 `(high[t-1], low[t])`
- 向下缺口：`high[t] < low[t-1]`，缺口區間 `(high[t], low[t-1])`
- 向上缺口回補：之後第一個 `low[k] <= high[t-1]` 的日期
- 向下缺口回補：之後第一個 `high[k] >= low[t-1]` 的日期
- 費半、Nasdaq 的 OHLC 來自 Yahoo（非官方），缺口結果需標示資料來源

### 漲跌家數
使用 TWSE「股票」欄（不含權證、ETF），上市與上櫃分開保存，合併時直接相加（兩市場不重複）。

| 項目 | 原因 | 建議做法 |
|---|---|---|

| 漲跌家數 2012 年以前／中間缺漏 | 部分日期回應沒有該表 | 回補時逐日記錄缺漏，必要時用個股行情自算 |

## 6. 最低成本資料架構建議

- **全部免費**：官方來源＋FRED（建議申請免費 API key）＋Yahoo（美股）＋FinMind 免費帳號（只用來補期貨籌碼舊資料）。
- **每日兩次批次**：
  - 台灣時間 約 21:30：台股、期貨、法人、融資（融資在晚間才公布，官方註明以隔日「前日餘額」為準，隔日批次要回頭修正前一日）。
  - 台灣時間 約 07:30：美股、FRED、匯率（FRED 本身延遲 1～2 日，要以資料的 `as_of_date` 為準，不要以抓取日期為準）。
- **每個來源一個 adapter**，輸出統一格式：`(series_id, as_of_date, value, source, fetched_at, revision)`。原始回應另存檔（JSON／CSV 原文），格式改版時可以重新解析。
- **限速**：TWSE 每次請求間隔 ≥ 5 秒、遇 307 退避重試；TAIFEX 歷史 CSV 單次查詢一個月內。
- **儲存**：SQLite 或 DuckDB 單檔即可。完整回補估計：TWSE 月資料約 300 個月 × 數個端點，逐日資料（漲跌家數、法人、融資）約 5,000 個交易日 × 3 端點 × 5 秒 ≈ 21 小時，需要可中斷續跑的回補工具。
